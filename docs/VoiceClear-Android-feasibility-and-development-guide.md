> 编制日期：2026-11-13

## 0. 阅读约定与结论摘要

### 0.1 证据标记

- **[事实]**：已从原始需求、官方资料或同行评审资料中核到的内容。
- **[建议]**：基于当前证据提出的工程或产品决策，仍需通过实验或用户研究验证。
- **[假设]**：因用户尚未确认而采用的暂定边界，不能视为用户决定。
- **[待验证]**：缺少足够证据，禁止据此作交付、性能或许可证承诺。

本次调研后段，联网检索服务出现 402 配额错误，无法继续补查所有候选项目。因此本文只把已核到的资料作为事实依据；没有核到的内容明确保留为待验证项，不以推测补齐。

### 0.2 一句话结论

**[建议] 项目有条件可行，但应从“单一目标人群、面对面交流、可解释的 ASR→文本→TTS 级联基线、严格内容保真评测”开始；端到端 S2S、全端侧实时推理和多类障碍通用能力应作为后续验证目标，而不是首版既定能力。**

### 0.3 关键决策摘要

| 决策 | 当前建议 | 原因 | 状态 |
|---|---|---|---|
| 首版人群 | 暂定普通话成人、听障相关发音不清，先只做一个人群 | 不同病因和言语表现的识别、合成及评价目标不同 | [假设]，待用户确认 |
| 首版场景 | 用户主动触发的面对面表达 | 可回避普通电话音频注入限制，先验证真实用户价值 | [建议] |
| 技术基线 | ASR→最小文本处理→TTS，输出仍为语音 | 可观察、可纠错、可分模块优化，便于建立对照 | [建议] |
| 端到端 S2S | 仅作为有退出条件的研究分支 | 数据、内容保真、音色保持和端侧实时性证据不足 | [建议] |
| 个性化训练 | 受控开发机或服务器训练，模型经授权下发 | 手机不适合作为首版训练环境，训练与推理应分开评估 | [建议] |
| 日常推理 | 以端侧为目标，先实测再承诺 | 隐私和弱网更有利，但质量、内存、温升和延迟未知 | [待验证] |
| 内容安全 | 低置信度不强行生成；支持原文查看、原始语音回放 | “清晰但错误”比“不够清晰”可能造成更严重的沟通后果 | [建议] |
| 成功标准 | 以目标用户可懂度、内容错误、身份接受度和任务完成率为主 | STOI、PESQ 或通用 ASR 分数不能独立代表真实效果 | [建议] |

### 0.4 暂不纳入首版的事项

1. 覆盖所有言语障碍类型和所有严重程度。
2. 普通电话或任意第三方通话 App 的实时语音替换。
3. 医疗诊断、康复治疗、紧急通信或高风险自动表达。
4. 未授权的声音复刻、公开声纹模型市场或社交分享。
5. 在未完成质量和隐私验证前默认上传原始语音。
6. 在没有真实设备数据前承诺固定延迟、固定注册时长或全机型离线运行。

## 1. 对原始需求 v0.2 的审查与修订

### 1.1 值得保留的产品原则

1. **表达效率优先**：相比图片或纯文字 AAC，语音转语音有机会保留更自然的交流节奏。
2. **优先提升可懂度**：不追求复杂语义润色，符合辅助表达定位。
3. **重视用户自己的声音**：声音身份对自我认同和社交参与重要，应作为独立研究目标。
4. **重视隐私和离线能力**：语音、健康信息和 voice profile 都需要最小化处理。
5. **保留技术路线开放性**：原文已把端到端方案写成待讨论路径，这是正确的决策方式。

### 1.2 需要修订的关键假设

| 原文假设或缺口 | 风险 | 修订指导 |
|---|---|---|
| 多类障碍可共用首版模型 | 听障发音、神经源性构音障碍、喉部病变和口吃并非同一任务 | 首版锁定一个人群，其他人群建立独立需求与评价分支 |
| “完全不经过文字”是硬约束 | 排除了更容易验证和纠错的级联路线，却不能自动保证内容不变 | 改为“用户以语音表达为主，内部是否使用文本由效果决定” |
| 单人几小时数据即可稳定个性化 | 效果依赖病因、严重度、文本覆盖、跨会话变化和基础模型 | 用注册时长消融实验确定，不预先承诺 |
| 公众可懂度提升可由客观指标代表 | STOI/PESQ 等依赖参考或特定失真假设，生成语音可能不适用 | 以独立听众盲测和逐说话人结果为主，客观指标为辅 |
| 端到端模型天然更保留音色 | 离散内容表示、目标声学表示和解码过程都可能丢失身份或引入内容错误 | 必须通过用户本人及听者评价验证，不能由架构推断 |
| 通用降噪可默认开启 | 降噪可能削弱微弱发音、鼻音、气息或停顿等有效线索 | 保留原始音频，降噪作为可消融模块 |
| 流式识别是首版必选项 | 长停顿、重复、阻塞会导致端点切分错误，流式还会增加状态复杂度 | 首版按键说话；在真实数据上验证后再引入流式 |
| 公开中文数据足以启动产品训练 | 数据规模、领域和授权范围不一，公开数据不能代表所有目标用户 | 公开数据用于预研；自由交流能力需要合规的目标人群数据 |
| 开源项目可直接作为核心依赖 | 项目存在不等于质量、许可证、维护和端侧适配均满足要求 | 建立 API、模型、许可证和维护性验证表 |
| 面对面与通话可共用首版音频链路 | Android 对通话音频有额外限制，且通话还涉及对端、网络与运营商链路 | 首版只做面对面，通话另立可行性项目 |
| 隐私只需“默认本地处理” | 个性化训练、崩溃日志、模型更新和数据分析仍可能产生数据流 | 对原始音频、文本、健康信息和 voice profile 分别建立生命周期 |

### 1.3 首版产品定义建议

**产品目标**：帮助特定普通话言语障碍用户在面对面交流中，更准确地表达其本来想说的话，并尽可能保留其认可的声音身份。

**产品不是**：通用语音美化器、自动替用户组织观点的助手、医疗诊断或治疗工具。

**首要用户任务**：

1. 用户按住或点击开始说话。
2. 用户明确结束输入；应用显示可访问的处理状态。
3. 系统识别并检查内容置信度。
4. 默认自动合成；用户可在设置中开启“播放前查看/编辑/确认文本”。
5. 对方听到合成语音；用户可重播、停止或播放原始语音。
6. 低置信度、模型异常或音频路由异常时，不强行输出猜测内容。

## 2. 人群、场景与可行性边界

### 2.1 人群不能混为一个类别

| 人群 | 主要技术差异 | 首版建议 |
|---|---|---|
| 听障相关发音不清 | 可能涉及音位、韵律、音量及听觉反馈差异；中文目标数据有限 | 作为暂定首选，但仍需专业顾问和用户共创 |
| 脑瘫等神经源性构音障碍 | 说话人之间及不同严重度差异大，可能伴随运动控制和疲劳问题 | 独立分层研究，不与听障数据直接合并承诺 |
| 声带/喉部病变 | 可能涉及气息、嘶哑、失声或替代发声方式，部分样本不适合常规 ASR/TTS | 先判断是否属于语音识别还是替代发声任务 |
| 口吃等流畅性障碍 | 重复、阻塞、长停顿和逃避行为影响端点及文本目标 | 独立设计端点与交互，不能把“去除所有不流畅”等同于用户意图 |
| 混合型或未明确诊断人群 | 标签不清、评价不可复现、模型错误难定位 | 不用于首版笼统验收 |

### 2.2 有条件可行的六个层面

| 层面 | 当前判断 | 可行条件 |
|---|---|---|
| 产品价值 | 有条件可行 | 用户愿意使用；处理延迟和额外确认不会抵消表达收益 |
| 级联算法 | 适合优先验证 | 目标人群 ASR 能达到可用基线；内容错误可控；TTS 可接受 |
| 端到端 S2S | 研究可行性待证 | 有匹配数据、内容监督、音色评价和稳定推理，并优于级联基线 |
| Android 端侧产品化 | 工程可探索，性能未证实 | 选定模型后通过真实设备质量、内存、温升、耗电和延迟测试 |
| 多类障碍通用 | 首版不可承诺 | 需要跨病因、跨严重度的数据和分层验证 |
| 普通电话集成 | 不纳入当前可行性结论 | 需单独解决平台权限、音频路由、对端体验和合规问题 |

### 2.3 启动产品化前必须满足的条件

1. 能招募目标用户参与共创、数据采集和盲测，并有言语康复或相关专业顾问。
2. 能合法获得覆盖目标场景的数据，并证明训练、模型发布和商业用途的授权链。
3. 级联基线在目标用户上相较原始语音带来明确收益，且关键内容错误处于用户和顾问接受范围内。
4. 至少一档真实目标设备满足质量与交互预算，或有经用户同意的替代部署路径。
5. 用户可以随时撤回数据、删除 voice profile，并在模型失败时使用原始表达方式。

## 3. 技术路线比较与架构决策

### 3.1 路线比较

| 路线 | 内容可解释性 | 数据要求 | 音色保持 | 实时工程 | 当前定位 |
|---|---|---|---|---|---|
| 通用降噪/语音增强 | 高，通常不改文本 | 相对较低 | 通常保留原声学特征 | 较容易 | 只能作为消融模块，不能解决多数发音修正 |
| ASR→文本→通用 TTS | 高，可检查和纠错 | 可从通用模型开始 | 通常不保留用户音色 | 可分层优化 | 必做质量与交互基线 |
| 个性化 ASR→文本→个性化 TTS | 高，可分别定位识别和合成错误 | 需要目标用户授权数据 | 有望改善，需主观验证 | 模型更大，需端侧实测 | 首版主要研究方向 |
| 直接 S2S/离散单元转换 | 通常较低，需要额外内容监督 | 平行或非平行数据设计复杂 | 架构上有潜力，但不能预设 | 依赖具体模型和流式实现 | 有条件的研究分支 |
| 混合方案 | 中等至较高 | 取决于内容、声学和说话人模块 | 可调，但系统复杂 | 模块多、验证成本高 | 后续探索，不在首版并行铺开 |

### 3.2 ADR-001：先建立级联基线

**决策**：以“ASR→最小必要文本规范化→TTS”作为首版技术基线，先验证通用 ASR/TTS，再逐步加入个性化模块。

**理由**：

1. 可以分别判断问题来自采集、识别、文本处理还是合成。
2. 文本可提供用户确认、错误审计和模型评测锚点。
3. 通用 TTS 能建立“只追求可懂度”的下限，个性化 TTS 再评估音色增益。
4. 端到端 S2S 必须有同一批用户、同一测试集上的对照对象，才能证明其优势。

**撤回或修改条件**：若级联方案在用户测试中长期无法满足交互或音色目标，而 S2S 在相同数据、内容和延迟约束下稳定优于它，可以重新决策。撤回依据必须是实验结果，而不是架构偏好。

### 3.3 文本处理红线

1. 不使用生成式模型自动补写用户没有表达的意图。
2. 不擅自改变否定、数量、时间、姓名、地点和指代。
3. 标点、大小写、数字读法等规范化必须可追踪，不得改变语义。
4. 语言模型重排序或纠错必须保留原始识别候选，并进行逐用户置信度校准。
5. 对低置信度或高风险内容，优先询问、显示候选或退回原始语音，不“流畅化猜测”。
6. 用户修改后的文本是否可保存或用于训练，必须独立授权。

### 3.4 S2S 研究分支的进入条件

只有同时满足以下条件才启动：

- 已有稳定的级联基线、目标用户测试集和内容保真指标。
- 已明确训练对是平行、非平行还是合成目标，以及这种设计带来的偏差。
- 能防止训练/测试说话人、注册语句和测试语句泄漏。
- 能评价音色、内容和可懂度，而不只评价音频听感。
- 有明确算力、数据和停止条件，不以“跑通 Demo”作为成功。
- 输出模型可导出、可审计，并有明确许可证和发布权。

## 4. 系统架构与模块设计

### 4.1 逻辑架构

~~~text
用户输入
   │
   ▼
音频采集与明确端点 ───────► 原始音频临时缓存 ───────► 原始回放/用户删除
   │
   ▼
预处理与质量检查
   │
   ▼
识别引擎适配层 ◄────────── 模型版本/用户适配配置
   │
   ▼
识别结果与置信度控制
   │            │
   │            └──── 低置信度 ──► 确认/候选/重试，不强行合成
   ▼
最小文本规范化（可审计）
   │
   ▼
合成引擎适配层 ◄────────── 通用声音或已授权 VoiceProfileRef
   │
   ▼
播放控制/音频焦点/路由处理
   │
   ▼
用户停止、重播、修改文本或播放原始语音

本地指标：各阶段耗时、错误码、模型版本；默认不记录原始音频和完整文本。
~~~

### 4.2 模块职责

| 模块 | 职责 | 不应承担的职责 |
|---|---|---|
| 采集与会话状态机 | 开始/结束/取消、格式记录、音频焦点、路由变化 | 自动猜测用户意图、后台无感知常录 |
| 预处理 | 电平检查、必要的格式转换、可开关的降噪/回声处理 | 无对照地删除停顿或改变发音特征 |
| 识别引擎 | 输出文本候选、时间信息、可用置信度和错误 | 直接播放或自行改写内容 |
| 内容安全控制 | 阈值、候选、确认策略、高风险词错误审计 | 用通用置信度替代逐用户校准 |
| 合成引擎 | 按确认文本和 voice profile 生成语音 | 擅自增删文本、未经授权选择他人声音 |
| 播放控制 | 停止、重播、音量、路由、打断和反馈抑制 | 播放时继续无条件采集自身输出 |
| 数据与同意管理 | 授权、保留、撤回、删除、导出和模型版本关联 | 以服务必需为由捆绑训练授权 |
| 指标与诊断 | 本地性能、崩溃和错误统计 | 默认上传原始语音或完整表达内容 |

### 4.3 会话状态机

~~~text
Idle
  → Recording
  → Processing.Recognizing
  → [可选] AwaitingConfirmation
  → Processing.Synthesizing
  → Playing
  → Completed / Idle

任意状态 → Cancelled / Error
Playing → Interrupted（来电、音频焦点丢失、用户停止、路由变化）
Error → OriginalPlayback / TextFallback / Retry / Idle
~~~

**要求**：所有异步任务都绑定会话 ID；用户取消或开始新会话后，旧识别/合成结果不得覆盖新状态或继续播放。

### 4.4 逻辑数据契约

以下是设计契约，不是已创建的代码或持久化 schema。

| 对象 | 必需字段 | 关键约束 |
|---|---|---|
| AudioSegment | sessionId、原始格式、内部格式、时长、采集时间、质量标记 | 原始与处理后音频可区分；禁止把采样率写死为所有设备唯一值 |
| RecognitionResult | sessionId、原始候选、规范化文本、置信度、时间戳、模型版本、警告 | 规范化必须可回溯；无可靠置信度时显式标记 unknown |
| SynthesisRequest | sessionId、已确认文本、voiceProfileRef、语速/韵律策略、模型版本 | 文本必须来自已确认或允许自动处理的识别结果 |
| SynthesisResult | sessionId、音频引用、时长、模型版本、警告 | 过期会话结果必须丢弃 |
| VoiceProfileRef | 本地随机 ID、创建方式、授权范围、模型版本、创建/删除时间 | 不直接使用手机号、姓名或身份证号作为标识 |
| ConsentRecord | 授权类型、版本、时间、撤回时间、数据/模型关联范围 | 基本使用、训练、上传、voice profile 分开授权 |
| ProcessingMetrics | 各阶段耗时、设备档位、结果/错误、模型版本、内存与热状态 | 默认不含原始音频和完整文本；上传需另有授权 |

### 4.5 失败与降级优先级

1. 保留用户已输入内容，避免重复说话造成疲劳。
2. 提供原始语音回放和文本辅助。
3. 明确说明当前失败环节，不展示误导性的“成功”。
4. 可重试时采用相同会话或显式新会话，避免重复播放。
5. 模型损坏、缺失或不兼容时阻止启动对应能力，并回退到已验证版本。
6. 任何降级不得暗中开启云端上传。

## 5. 数据与模型工程指导

### 5.1 公开数据的正确定位

| 数据集 | 已核到的信息 | 可以支持 | 不能直接证明 |
|---|---|---|---|
| CDSD | Interspeech 2024 论文（arXiv:2310.15930）；官方数据集页称 44 名说话人、133 小时，其中一段版本描述为 24 名说话人、34 小时（2 小时测试 / 32 小时训练），规模以官方页最终口径为准 | 中文构音障碍识别方法预研、实验对照 | 覆盖听障、口吃、喉部病变或自由交流产品需求 |
| MDSC | 论文发布的中文构音障碍语料；论文报告相关部分约 9.4 小时，面向唤醒词和有限家居指令 | 特定说话人、关键词/唤醒和适配方法研究 | 长句、自发对话、广泛词汇和 TTS 个性化能力 |
| UA-Speech | 官方检索结果为英文构音障碍语音，含 CP 说话人 | 英文方法、跨说话人适配和评测设计参考 | 中文音位、声调及中文 TTS 的直接效果 |
| TORGO | 官方检索结果为英文构音障碍语音，含 CP/ALS 相关说话人及声学/发音数据 | 英文及多模态方法研究 | 中文目标人群产品效果 |

**许可证要求**：论文公开、可申请下载、研究使用和可商业发布是不同概念。正式使用前必须保存下载协议、许可证文本、授权日期、用途、再分发限制和模型衍生品条款。MDSC 的实际下载协议及 CDSD 数据许可证在本次检索中未完成核验，不得标成“可自由商用”。

### 5.2 自有数据采集设计

1. **人群分层**：记录由合适专业人员确认的类别和严重度；不在 App 内自行诊断。
2. **内容覆盖**：音位/声调覆盖朗读句、常用表达、数字与否定、姓名地名、自发描述和真实对话。
3. **跨会话**：不同日期、设备、距离和环境，避免把同一录音切成训练与测试造成“虚高分”。
4. **疲劳与可访问性**：允许随时暂停、跳过和撤回，不用长时间连续录制换取数据量。
5. **原始保留**：保留未经降噪的原始音频和完整采集元数据，处理版本必须可追溯。
6. **标注质量控制**：转写者培训、抽样复核、分歧处理、标注指南版本化和一致性统计。
7. **个性化隔离**：注册音频与测试音频分离；测试应包含未读过的句子和不同会话。
8. **测试集治理**：最终测试集尽量只读，模型选择使用独立开发集，防止反复调参导致测试集失真。
9. **意图基准**：朗读句使用预先批准的文本；自发表达由用户以其可访问的方式在录音后确认意图基准。确认文本不得提前提供给独立听者；无法可靠确认意图的样本单独标记，不强行纳入内容正确率统计。

### 5.3 ASR 指导

**基线顺序**：

1. 通用中文 ASR，在目标用户原始数据上只评估，不急于微调。
2. 分析错误是否集中于音位、声调、端点、词汇、语速、重复或录音质量。
3. 尝试有依据的说话人适配或参数高效微调；具体方法必须与所选模型真实能力一致。
4. 做注册时长、会话跨度和严重度分层消融，记录收益与退化。
5. 仅在确认不会增加关键语义错误时加入领域词表、语言模型重排序或纠错。

**禁止**：

- 用正常语音 CER/WER 推断言语障碍用户效果。
- 只看所有用户合并均值，掩盖严重用户退化。
- 用同一个 ASR 生成训练文本又作为唯一评测裁判。
- 为提高“识别率”而删除难以识别但具有真实语义的片段。

### 5.4 TTS 与音色个性化指导

1. 先用已授权、清晰的通用中文声音建立可懂度和交互基线。
2. 个性化 TTS 与通用 TTS 必须在相同文本、相同听者和相同设备上比较。
3. 注册时长不是固定常数，应测试多档时长、文本覆盖和噪声条件。
4. 音色保持至少包括：用户本人接受度、熟悉听者判断、独立听者同人/异人判断；嵌入相似度只作辅助。
5. 检查合成语音是否改变情绪、语速、节律或自我认同，不能只追求“像正常人”。
6. 若用户没有可合法使用的清晰语音，不能假定通用模型能无代价恢复其“原本声音”。
7. voice profile 视为高敏感资产，禁止未授权交换、公开下载或用于其他说话人。

### 5.5 预处理与流式策略

- 原始音频始终作为对照；降噪、增益、回声消除和 VAD 均做独立消融。
- 首版优先用户明确开始/结束，减少长停顿和阻塞导致的截断。
- 后续流式识别要区分“部分结果”和“最终结果”，部分文本不能直接触发最终合成。
- 播放时避免采集自身输出；需要全双工时，必须在真实设备上验证回声消除和双讲，而不是只在模拟器测试。
- 对口吃用户，不应默认把重复、停顿全部视作噪声删除，须与用户确认目标。

### 5.6 候选组件与 API 验证表

下表只表示预研候选，不代表最终选型或许可证已通过。

| 能力 | 候选/线索 | 当前证据状态 | 进入实现前的门槛 |
|---|---|---|---|
| 中文 ASR 训练与推理 | FunASR、Paraformer 模型族 | 已核到官方仓库与模型说明；目标人群效果未知 | 固定版本、核查代码和模型许可证、跑目标数据基线 |
| Android 推理 | ONNX Runtime Android/Java | 已核到官方 Android/Java 文档入口 | 验证具体 opset、算子、线程、包体和真实设备兼容性 |
| 端侧语音集成 | sherpa-onnx | 已核到官方项目检索结果 | 验证所需 ASR/TTS 模型是否真实支持、许可证及性能 |
| 音频采集 | Android 官方音频 API | 已核到 MediaRecorder.AudioSource 官方说明 | 按选定 API 级别重新核对权限、格式和路由；先写 API 验证表 |
| 通话音频 | VOICE_CALL 等音频源 | 官方文档明确存在能力/权限限制 | 首版禁用；另立系统权限和平台可行性项目 |
| VoiceRestore | 通用语音修复，仓库为 skirdey/voicerestore（论文 arXiv:2501.00794，Flow-Matching Transformer） | 已核到仓库与论文；定位是**通用去噪/去混响/音质恢复**，不是构音障碍专用模型 | 只能作为"通用降噪"消融基线，不得当作言语障碍解决方案 |
| SIDON | 通用多语种语音修复与数据清洗，仓库为 sarulab-speech/Sidon（论文 arXiv:2509.17052，CC BY 4.0） | 已核到论文与仓库；目标是**大规模数据集清洗**，不是构音障碍 S2S | 仅可用于训练数据清洗环节评估，不进入表达链路 |
| 构音障碍专用 S2S 研究 | 已核到三条相关路线：DiffDSR（差分离散单元建模）、Conditional Flow Matching 声学/内容解耦、基于自监督表征的两阶段 VC（arXiv:2503.24600） | 论文存在且以 UA-Speech/TORGO 等为主要评测集；**均为英文与英文构音障碍人群**，中文场景未验证 | 作为 P3 研究分支的文献基线；须先在中文目标人群上复现基线再评估 |
| 个性化中文 TTS | 尚未选定 | 当前证据不足 | 至少比较质量、音色、端侧性能、模型授权和撤回能力 |

## 6. Android 软件工程指导

### 6.1 推荐分层

~~~text
UI 与无障碍交互
  └─ 会话/播放状态机
      └─ 用例层：识别、确认、合成、回放、撤回
          ├─ 语音引擎适配接口
          ├─ 音频采集与播放接口
          ├─ 同意与数据生命周期
          └─ 指标与诊断
              └─ Android/原生实现及可替换模型运行时
~~~

UI 不直接调用模型；模型实现可以替换为假引擎进行确定性测试。任何网络实现都必须是显式、可关闭、可审计的独立实现。

### 6.2 音频链路要求

1. 记录设备实际采集格式和模型要求格式，重采样前后均保留质量信息。
2. 不假设模拟器麦克风、蓝牙和扬声器行为与真机一致。
3. 处理电话、闹钟、其他媒体、耳机插拔、蓝牙断连和音频焦点变化。
4. 播放期间提供显著停止按钮；新会话必须停止旧播放。
5. 默认避免应用听到自己的合成输出，防止循环识别和声反馈。
6. 对音量过小、削波、长静音和多人串音给出可理解的提示。
7. 原始语音默认短期本地保存；会话结束后的删除策略由同意与设置决定。

### 6.3 性能预算

定义用户感知延迟：

~~~text
T_total = T_endpoint + T_preprocess + T_ASR + T_confirm(自动模式为 0)
        + T_TTS + T_route_and_buffer + T_first_audible_frame
~~~

- 同时报告从“用户停止说话”和从“点击结束”开始的测量口径。
- 报告 p50、p95、最大值和失败率，不只报告平均值。
- 分别记录模型加载/卸载、首次推理、稳态推理、峰值内存、模型体积、耗电和热状态。
- 量化或裁剪前后必须运行相同质量测试集；速度提升不能掩盖内容错误增加。
- 延迟目标应在 P0/P1 由目标用户测试确定；当前不设无证据的统一毫秒承诺。

### 6.4 模型包与更新

每个模型包至少包含：

- 模型 ID、版本、构建来源和校验值。
- 支持的运行时、opset/算子、最低设备能力及包体大小。
- 训练数据版本、适用人群、语言、许可证和已知限制。
- 质量回归报告、性能报告和回滚版本。
- voice profile 与基础模型的兼容关系及删除/撤回方式。

更新失败不得破坏现有可用模型；未经用户授权不得把“模型更新”变成新的数据上传渠道。

### 6.5 最小真机测试矩阵

| 维度 | 至少覆盖 |
|---|---|
| 系统 | 计划支持的最低、主流和最新 Android/API 等级 |
| 设备能力 | 低/中/高内存与不同芯片档位；具体机型在 P0 确认 |
| 音频 | 内置麦克风、扬声器、有线耳机、蓝牙耳机 |
| 网络 | 飞行模式、弱网、网络切换；端侧模式不得暗中联网 |
| 会话 | 冷启动、连续多次、取消、覆盖新会话、后台/前台切换 |
| 环境 | 安静、噪声、混响、远近距离、不同音量 |
| 压力 | 长音频、低内存、热状态、低电量和存储不足 |
| 无障碍 | 屏幕阅读、大字体、高对比、单手操作、视觉/触觉反馈 |

## 7. 隐私、安全与伦理设计

### 7.1 数据分类

| 数据 | 风险 | 默认策略 |
|---|---|---|
| 原始语音 | 可识别个人，可能包含健康、情绪和环境信息 | 本地短期、明确保留期限、默认不上传 |
| 转写文本 | 可能包含姓名、联系方式、病情和私密表达 | 最小化日志，默认不保存完整内容 |
| 障碍类别/严重度 | 可能属于医疗健康等敏感个人信息 | 单独告知、特定目的、充分必要、严格保护 |
| voice profile/声纹 | 可能用于身份识别或冒用，泄露后难以更换 | 独立授权、加密、访问控制、可撤回和删除 |
| 模型与适配参数 | 可能反推个人特征或被迁移冒用 | 纳入个人数据影响评估和删除链 |
| 崩溃与性能日志 | 可能意外包含文本、路径或标识 | 字段白名单、去标识化、上传前授权 |

### 7.2 法规映射（工程提示，非法律意见）

《个人信息保护法》第 28、29 条涉及敏感个人信息及单独同意；第 31 条涉及不满十四周岁未成年人；第 47 条涉及删除；第 55、56 条涉及个人信息保护影响评估。项目应在实际数据流确定后，由合规人员核查适用条款、告知文本、同意记录、委托处理、跨境和保留期限。

**工程落地**：

1. 基本功能、云端处理、训练改进、voice profile 创建和对外分享分别授权。
2. 撤回训练授权后，按承诺处理原始数据、可识别副本、后续训练和可撤回模型资产。对已经进入不可逆聚合或全局模型的个人影响，须在授权前说明可撤回边界，不承诺技术上无法实现的“完全遗忘”。
3. 不把“匿名化 ID”误当作语音已匿名；声音本身可能仍可识别。
4. 若涉及未成年人、监护人或认知沟通障碍，需设计可理解、可撤回的同意流程。
5. 对外测试、论文、演示和示例音频同样属于数据处理，不因科研目的自动豁免。

### 7.3 威胁模型与防护

| 威胁 | 防护 |
|---|---|
| 原始音频或文本泄露 | 本地优先、最小采集、加密、短期保留、日志白名单 |
| voice profile 被复制冒用 | 设备绑定或受控存储、访问控制、禁止公开分享、撤回与删除 |
| 模型更新被篡改 | 签名/校验、受信来源、版本回滚、失败隔离 |
| 云端研究数据越权访问 | 最小权限、审计、环境隔离、委托处理协议、到期删除 |
| 合成内容改变用户意图 | 文本可追踪、关键错误测试、低置信度拒绝、原始回放 |
| 用户被强迫注册声音 | 提供通用声音或纯文字替代，不把个性化作为服务前置条件 |

## 8. 评测体系与验收方法

### 8.1 核心研究问题

1. 与原始语音相比，陌生听者是否正确理解了更多用户本意？
2. 合成语音是否遗漏、替换或新增了关键内容？
3. 用户本人是否接受输出声音，熟悉听者是否仍能辨认其身份？
4. 改善是否覆盖不同严重度和不同会话，还是只集中于少数轻度用户？
5. 真实交互延迟、确认负担和疲劳是否仍让应用有实际价值？
6. 个性化方案是否显著优于更简单的通用 ASR/TTS 基线？

### 8.2 实验分组

至少比较：

- A：原始语音。
- B：必要预处理后的原始语音（若有）。
- C：通用 ASR→通用 TTS。
- D：个性化 ASR→通用 TTS。
- E：个性化 ASR→个性化 TTS。
- F：S2S 研究方案（达到进入条件后）。

实验使用同一用户、同一语义内容和可比环境；音频顺序随机化并平衡，听者尽量不知道条件，避免把“更电子、更正常”直接当成“更准确”。

### 8.3 指标体系

| 维度 | 主要指标 | 注意事项 |
|---|---|---|
| 可懂度 | 独立听者转写 CER、关键词/句意正确率、任务完成率 | 中文需明确字、词和分词口径；逐说话人报告 |
| 内容保真 | S/D/I、关键语义错误、否定/数字/专名错误 | 与原始人工转写和用户意图核对 |
| 音色身份 | 用户接受度、熟悉者辨认、独立听者同人/异人判断 | 嵌入相似度仅辅助，不等于身份接受 |
| 听感 | 自然度、稳定性、可听疲劳、异常音 | 自然度不能覆盖内容错误 |
| 交互 | 完成时间、重试次数、确认负担、停止/纠错成功率 | 记录用户疲劳和自主控制感 |
| 性能 | 分阶段及端到端 p50/p95、首音时间、失败率 | 统一计时口径，真机测量 |
| 资源 | 峰值内存、包体、模型大小、耗电、温升 | 首次与稳态、冷启动与连续运行分开 |
| 公平性 | 病因/严重度/年龄/性别/设备等分层退化 | 小样本只作探索，不做过度统计推断 |

中文转写可定义：

~~~text
CER = (替换字数 S + 删除字数 D + 插入字数 I) / 参考总字数 N
~~~

同时保留句意和关键词评价，避免一个不影响含义的字符差异与一个否定词错误被等同看待。

### 8.4 客观指标的边界

- **STOI**：主要用于特定侵入式可懂度预测，需要合适参考和失真假设；不能独立证明自由生成语音的可懂度。
- **PESQ**：用于特定语音质量/编解码与传输失真评价，不是内容保真或声音身份指标。
- **DNSMOS**：可提供听感相关参考，但不应替代目标用户和陌生听者测试。
- **通用 ASR 回译 CER**：可能偏向“更容易被该 ASR 识别”的声音，而非人类真实理解；与训练使用同一 ASR 时还存在循环偏差。
- **声纹相似度**：依赖声纹模型对目标人群的适用性，不能代替用户本人评价。

### 8.5 统计与报告要求

1. 训练、开发、测试按说话人隔离；个性化注册和测试按会话/语句隔离。
2. 预先确定主要指标、排除规则和通过/停止条件，避免事后挑选有利指标。
3. 报告逐用户分布、置信区间或适合小样本的区间估计，不只报告平均值。
4. 听者转写需要抽样复核和一致性评价；分歧处理规则预先写明。
5. 在内部评测报告中呈现失败案例，包括内容改错、严重用户退化、延迟过高和身份不被接受；对外展示必须另行授权并进行适当去标识化。
6. 最终阈值由 P0 的产品负责人、目标用户和专业顾问基于基线共同批准，本文不虚构统一通过数值。

## 9. 测试与失败场景清单

### 9.1 测试层级

| 层级 | 内容 | 通过证据 |
|---|---|---|
| 静态检查 | Kotlin/原生代码 lint、类型与并发检查、依赖和许可证扫描 | 无阻断问题，报告可追踪 |
| 单元测试 | 重采样、会话 ID、取消、状态转换、文本规范化、保留期限 | 确定性和边界用例通过 |
| 集成测试 | 假 ASR/TTS、慢结果、乱序结果、模型错误、路由变化 | 无旧结果覆盖、无错误播放 |
| 模型回归 | 固定版本数据、逐用户指标、关键语义错误、音色评价 | 与批准基线比较，无未解释退化 |
| Android 仪器化 | 权限、音频焦点、前后台、蓝牙、存储和进程恢复 | 真机结果，而非只跑模拟器 |
| 性能测试 | 冷/热启动、连续会话、长音频、低内存和热状态 | 原始指标及设备信息完整 |
| 隐私测试 | 飞行模式、撤回、删除、日志字段、更新过程 | 无未授权网络和内容泄露 |
| 无障碍测试 | 屏幕阅读、大字体、高对比、触觉反馈、单手操作 | 目标用户与自动化/人工检查 |
| 用户试点 | 对照盲测、任务完成、可理解性和自主性 | 预先批准的验收报告 |

### 9.2 必须覆盖的失败用例

1. 空音频、极短音频、超长安静段、说话过程中取消。
2. 长停顿、字词重复、阻塞、多人同时说话。
3. 否定词、数字、药名、姓名、地址和中英文混说。
4. 低置信度、ASR 空文本、多个相互矛盾候选。
5. TTS 生成空音频、截断、异常音或结果迟到。
6. 模型缺失、校验失败、版本不兼容、运行时报错。
7. OOM、过热、低存储、低电量和进程被系统回收。
8. 用户开始新会话时旧识别/合成结果返回。
9. 播放中来电话、音频焦点丢失、蓝牙耳机断开。
10. 离线、弱网、网络切换；端侧配置不得发起隐藏请求。
11. 用户撤回授权、删除 voice profile 或清除全部数据。
12. 用户要求原始回放、停止播放、修改文本或改用纯文字。

**统一原则**：失败时不得静默生成“清晰但未经确认”的内容；不得因重试而重复上传或重复播放。

| 范围蔓延 | 高/中高 | 首版同时要求通话、多病种、全离线、S2S | ADR 和阶段门控制；新增目标必须重新估算数据与验证成本 |

## 12. 对原始需求五个问题的直接回答

### Q1：严格“不经过文字”是否最优？

**不是应预设的最优约束。** 对首版而言，内容可验证、错误可定位、用户可纠正更重要。允许内部使用文本并不改变产品“语音输入、语音输出”的定位。应把严格 S2S 作为实验变量，而不是产品价值本身。

### Q2：端到端 S2S 是否比级联更适合？

**当前证据不足以作此结论。** 级联方案更适合建立基线；S2S 可能在保留部分声学特征或减少模块误差传播方面有潜力，但也可能降低可解释性并增加数据与调试难度。必须在同一用户、同一内容、同一设备和同一评价协议下比较。

### Q3：如何平衡内容保真、音色和延迟？

优先级建议为：

1. 不改变用户意图，失败可恢复。
2. 真实可懂度和任务完成有提升。
3. 交互延迟和额外操作在目标用户可接受范围内。
4. 在前述条件满足后优化音色个性化，不用音色收益交换内容安全。

具体阈值通过目标用户基线测试确定，而不是给三个指标任意分配固定权重。

### Q4：中文言语障碍数据是否足够？

**公开数据可以支持预研，但不能据此证明自由交流产品可行。** CDSD、MDSC 的规模、内容和人群均有限；英文 UA-Speech/TORGO 可提供方法参考，但不能替代中文目标用户数据。需尽快建立合规、分层、跨会话的小规模高质量数据与评测集，并逐阶段判断是否扩量。

### Q5：哪些指标最合理？

主要指标是独立听者真实理解、关键内容错误、用户任务完成和本人音色接受度；工程指标包括端到端 p50/p95、失败率、峰值内存、耗电和温升。STOI、PESQ、DNSMOS、通用 ASR 回译和声纹相似度只能作为有明确边界的辅助指标。

## 14. 待用户确认的决策

此前交互提问因等待超时未收到选择，所以以下仍是开放项：
