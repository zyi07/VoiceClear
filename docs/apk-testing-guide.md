# VoiceClear 首代 APK 真机测试指引

> 版本：v1.0  
> 构建日期：2026-11-13  
> APK：`app-debug.apk`（debug 签名，可直接安装）

## 1. 安装

```bash
# 方法一：直接传文件
adb install -r VoiceClear-debug.apk

# 方法二：先推到手机再安装
adb push VoiceClear-debug.apk /sdcard/Download/
adb shell pm install -r /sdcard/Download/VoiceClear-debug.apk
```

**要求**：Android 8.0（API 26）及以上。首次启动需授予麦克风权限。

## 2. 首次启动：下载识别模型（重要）

本版本接入了**真实的端侧离线识别引擎**（SenseVoice），但模型约 239 MB，不随 APK 发布。

首次启动会进入「准备离线识别模型」页面：

1. 点「下载识别模型（约 239 MB）」
2. 保持网络连接，等待进度条完成（几兆到几十兆速度，取决于网络）
3. 完成后自动加载引擎，回到主界面

**下载会自动降级**：优先从 ModelScope（魔搭，国内直连）下载；若不可达，
自动切换到 GitHub Release（官方归档）。界面会显示当前使用的来源。

**如果提示没有网络**：检查手机是否真的连着网，以及是否开启了「仅 Wi-Fi 时下载」之类的
系统限制。应用需要 INTERNET 权限才能下载模型（v0.3 及之前版本因清单疏漏
漏声明该权限，导致下载必然失败，已修复）。

**下载中断可续传**：移动网络断了再连上，重新点下载会从断点继续，不用从头下。

**主界面会显示模型状态**：

- 「离线识别模型已就绪（xxx MB）」 → 可用
- 「离线识别模型未就绪，当前无法识别语音」 → 点「下载识别模型」

模型未就绪时**录音按钮会拒绝启动**，避免产出无法识别的无效音频。

> 注意：不要把「模型未就绪」时的识别结果当成真实结果——那一版用的是占位引擎。

## 3. 抓日志（两种方式，可同时用）

### 方式一：adb logcat（推荐，实时）

```bash
# 只看 VoiceClear 的日志
adb logcat -s VoiceClear:V

# 带时间戳与线程信息
adb logcat -v threadtime -s VoiceClear:V

# 先清空再操作，避免历史日志干扰
adb logcat -c
adb logcat -v threadtime -s VoiceClear:V > voiceclear-log.txt
```

### 方式二：App 内导出（无需连电脑）

主界面底部「**导出诊断日志**」按钮 → 选择保存位置 → 得到 `voiceclear-log-*.txt`。

两种方式内容一致：方式一实时、适合交互过程；方式二可留存、可直接发文件。

## 3. 日志内容说明

日志**不含原始音频，也不含完整表达文本**，只含元信息与错误码：

| Tag | 内容 |
|---|---|
| `Session` | 会话开始、ID 前 8 位 |
| `Capture` | 采集耗时、时长、采样率、质量标记 |
| `Recognition` | 识别耗时、置信度、**文本长度**（不含内容） |
| `Synthesis` | 合成耗时、警告码 |
| `Playback` | 播放耗时 |
| `Metrics` | 各阶段耗时与结果状态 |
| `Error` | 错误信息 |
| `Log` / `Export` | 日志导出与音频导出过程 |

## 4. 建议测试路径

### 4.1 基础功能（含真实识别）

1. 启动 App → 授予麦克风权限
2. 点「开始说话」→ 说一句中文 → 再点一次「停止」
   （录音是**两段式**的：点开始立即录音，点停止才停止并开始识别）
3. 观察是否出现「识别文本」框 → 文本是否可编辑
4. 点「确认并播放」→ 听到合成语音
5. 点「播放原始语音」→ 听到自己的原声
6. 点「取消」→ 应能中断

**请记录**：

- 你的手机型号与 Android 版本
- 从停止说话到出现识别文本的**大致秒数**（这是最关键的体验指标）
- 识别文本与您实际说的话差多少（完全一致 / 差几个字 / 完全不对）
- 是否听到合成语音；听起来是否清楚、是否像你
- 是否有卡顿、闪退、听不见、重复播放等情况

### 4.2 边界场景（每个都试一下）

| 场景 | 操作 | 关注点 |
|---|---|---|
| 长停顿 | 说完后停 3 秒再点停止 | 是否被提前截断 |
| 极短语音 | 只说「嗯」一个字 | 是否有异常提示 |
| 快速连续操作 | 连续快速点停止/播放 | 是否状态错乱 |
| 来电打断 | 播放中接个电话 | 是否自动停止、能否恢复 |
| 蓝牙耳机 | 连蓝牙耳机后重复 4.1 | 录音与播放是否走耳机 |
| 静音模式 | 静音后播放 | 是否能听到 |
| 飞行模式 | 开飞行模式 | 是否仍可用（应为纯本地） |
| 后台切换 | 播放时切到其他应用再回来 | 状态是否正常 |

### 4.3 采集模式

主界面「**采集模式**」→ 选提示句 → 录音 → 看是否正确入库与统计。

**注意**：采集模式用于经伦理审查批准的研究采集，正式使用前请勿用它采集真实用户数据。

## 5. 反馈时请附上

1. `voiceclear-log.txt`（adb logcat）或 App 导出的 `voiceclear-diagnostics-*.zip`
   （含日志、崩溃记录、设备快照、性能指标）
2. 手机型号 + Android 版本 + 是否使用蓝牙耳机
3. 上述每一步的实际表现，特别是**耗时**与**识别准确度**
4. 任何异常（闪退、无响应、权限问题）的**发生时机**

## 6. 已知限制（测试时请预期到）

- **识别准确率未知**：SenseVoice 在普通说话人上的公开基准是 CER 7.81%，
  但**目标人群（听障相关发音不清）的真实准确率没有数据**。
  这一版第一次能测到真实识别，请如实记录识别错误的类型（哪些字错、错成什么）。
- **无置信度**：SenseVoice 不提供 token 级置信度，界面不会显示置信度百分比。
  这是模型能力限制，不是 bug。
- **合成用系统 TTS**：声音是通用音色，不保留你的个人音色。
- **端侧性能未验证**：首帧延迟、内存占用、温升需要真机数据才能评估。
  239 MB 模型常驻内存，中低端机可能吃紧——请反馈是否卡顿或被系统杀进程。
- 未做真机适配测试：这是第一次在真机上运行，
  音频路由、焦点抢占、后台行为都可能暴露问题——这正是本次测试的目的。

## 第 7 轮测试：麦克风音源对比（2026-11-16 起）

### 为什么需要这轮测试

第 6 轮日志显示 7 次录音中 5 次**几乎没有声音**（RMS ≤ 0.0001），
模型在这些输入上产生了幻觉输出（`<|en|>`、`<|ko|>` 等无意义内容）。
本轮要解决的是**采集质量**，不是识别算法。

### 测试步骤

1. 打开 App，点「麦克风设置」→ 选「原始声音（推荐）」。
2. 把手机放在**离嘴约 15-20 厘米**处（不要贴着桌面，避免桌面反射）。
3. **用同一句话**朗读 5 次，每次 2-4 秒。
4. 点「导出日志」，把 zip 发回来。
5. 重复步骤 1-4，但音源选「语音识别优化」。
6. 再发一次日志。

### 关键要求

- **两次必须是同一句话**。否则无法比较。
- 每次录音**时长尽量一致**（2-4 秒）。
- 说话时**不要捂嘴**，也不要刻意提高音量——
  我们要测的是「自然状态下的发音」，不是「最大音量下的发音」。
- 如果在嘈杂环境测，另做一组并**在消息里说明环境**。

### 日志里要看什么

| 字段 | 含义 | 好的结果 |
|---|---|---|
| `RMS` | 录音能量 | > 0.01（实测 0.0446 是正常说话） |
| `峰值` | 最大振幅 | 0.05 - 0.8 |
| `音频质量` | 判定档位 | `NORMAL`（正常） |
| `文本长度` | 识别出的字数 | 明显大于 2 |
| `语言` | 模型判定的语种 | `<\|zh\|>` |

### 如果看到「没有检测到声音」

新版会**提前拦截**近乎静音的录音并明确提示，不会再给出乱码。
遇到这个提示，请检查：

1. 麦克风是否被遮挡（有些手机壳会挡住底部麦克风孔）
2. 是否有其他应用占用麦克风
3. 换到**安静**的环境再试
4. 试试另一个音源设置
