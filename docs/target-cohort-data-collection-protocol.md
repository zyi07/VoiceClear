# VoiceClear-Android 目标人群数据采集协议（听障相关发音不清的普通话成人）

> 版本：v1.0（设计基线）  
> 编制日期：2026-11-13  
> 适用阶段：P0 数据准备 / P2 级联质量基线  
> 关联文档：《VoiceClear-Android 软件开发可行性研究与技术指导》v1.1  
> 状态：设计稿，未经伦理/合规审查，不得据此实际采集

## 1. 适用范围

本协议只适用于**听障相关发音不清的普通话成人**这一人群。神经源性构音障碍、声带/喉部病变、
口吃等人群需要独立协议，不在本文件覆盖范围内（可行性指南 2.1 节）。

人群定义采用「由具备资质的专业人员确认」的方式，不由 App 自行诊断，
也不以自述标签作为唯一依据。

## 2. 为什么需要独立协议

本协议的设计直接来自可行性指南中的三条已确认风险：

1. **多人群混用导致部分用户退化**（风险登记表）：不同病因的发音特征差异极大，
   合并训练与合并评测都会掩盖严重用户的退化。
2. **公开数据不足以支撑产品承诺**：CDSD、MDSC 属于构音障碍人群，不能替代本人群数据；
   听障相关发音不清的普通话数据在公开资源中更缺乏。
3. **指标虚高**（风险登记表）：会话切分、注册语句复用都会让评测结果虚高。

因此本协议的重点不是「多采数据」，而是**可控、可解释、可分层**的小规模高质量数据。

## 3. 分层设计

### 3.1 严重度分层

严重度由专业顾问依既有临床量表判定，记录为分层变量，用于分层报告，不用于产品内判定。

| 层级 | 说明 | 数据用途 |
|---|---|---|
| L1 轻度 | 偶尔影响理解，情境依赖 | 可用于基线与对照 |
| L2 中度 | 多数情境下影响理解 | 主要训练与评测人群 |
| L3 重度 | 持续显著影响理解 | 必须单独报告，不得用均值掩盖 |

**硬性要求**：每层至少 2 名说话人；任何一层不足 2 人时，该层结果只能作为探索性观察。

### 3.2 场景分层

| 场景 | 采集内容 | 目的 |
|---|---|---|
| 朗读 | 音位/声调覆盖句、常用表达、数字与否定、姓名地名 | 可控、可比较，建立 ASR 基线 |
| 自发表达 | 用户真实想说的话（如就医、购物、约见） | 检验真实场景下的内容保真 |
| 对话片段 | 与同伴的两三轮对话 | 检验连续交互与端点表现 |

### 3.3 会话分层

- 每个说话人至少 **3 个不同日期** 的会话；
- 至少覆盖 2 种设备（自有/借用）与 2 种环境（安静/轻度噪声）；
- 会话之间不得复用相同语句作为注册与测试素材；
- 同一会话的切片只能全部落在同一个数据划分内（禁止跨划分切片）。

## 4. 采集协议

### 4.1 知情同意要点

同意材料须单独说明并逐项选择，不得把「参与研究」与「使用产品」捆绑：

1. 参与共创与试用（可随时退出）；
2. 音频用于算法训练（可随时撤回，含后续模型的处理说明）；
3. 音频上传至受控服务器（默认关闭）；
4. 生成个人声音特征（voice profile）；
5. 匿名统计报告（不含可识别信息）。

撤回机制必须在前置说明中写明**可撤回的技术边界**：
已进入全局训练模型的个人影响无法保证完全移除，这一点不得含糊表述。

### 4.2 采集流程

```
预约与知情同意 → 设备与环境记录 → 基线朗读 → 自发表达 → 对话片段
        → 逐条意图基准确认 → 用户主观评分 → 当场回听 → 数据入库与校验
```

**逐条意图基准确认**是本协议的关键环节：

- 朗读句使用预先批准的文本；
- 自发表达由用户在其可访问的方式下确认「我本来想说的是」；
- 确认文本不得提前提供给独立听者，避免评测泄漏；
- 无法可靠确认意图的样本单独标记，不纳入内容正确率统计。

### 4.3 疲劳与可访问性

- 单次连续采集时长上限建议 20 分钟，出现疲劳迹象立即暂停；
- 提供随时跳过、暂停与撤回的按钮，不需要说明理由；
- 允许使用任何助听设备或辅助工具，不限制其使用；
- 记录当时的疲劳自评（1–5），作为分层变量之一。

### 4.4 录音要求

| 项目 | 要求 | 理由 |
|---|---|---|
| 采样率 | 保留原始设备格式，另存 16 kHz 单声道副本 | 保留原始供消融对照 |
| 降噪 | 原始音频不做降噪；降噪版本另存 | 降噪可能削弱微弱发音线索 |
| 环境 | 记录环境类型与估计噪声水平 | 支持分层消融 |
| 距离 | 记录手机与嘴的距离区间 | 距离直接影响可懂度 |
| 助听设备 | 记录是否佩戴及型号类型 | 影响麦克风输入 |

### 4.5 元数据最小集

每个音频片段至少记录：`sessionId`、`speakerId`（匿名）、`sessionDate`、`scene`（朗读/自发/对话）、
`severityLevel`、`promptId`（朗读句 ID 或空）、`referenceText`（意图基准）、`deviceModel`、
`environment`、`distanceRange`、`wearHearingAid`、`fatigueLevel`、`samplingRate`、
`channels`、`noiseEstimateDb`、`consentFlags`（各项授权）、`annotationGuideVersion`。

## 5. 数据划分与防泄漏

| 划分 | 用途 | 约束 |
|---|---|---|
| 训练集 | 模型训练 | 按说话人划分 |
| 开发集 | 调参与阈值选择 | 按说话人划分 |
| 测试集 | 最终报告 | 尽量只读，按说话人与会话双重隔离 |

**个性化注册集**必须与任何测试集分离：注册音频与测试音频不得来自同一会话、同一语句或相邻日期。
评测报告中须显式说明注册时长与测试间隔，否则个性化收益无法解释。

## 6. 标注与质量控制

- 转写由普通话母语者完成，至少两人独立转写分歧样本；
- 标注指南版本化，指南变更需重训转写员；
- 每月抽样复核 10%，统计转写一致率（可用字符一致率近似）；
- 分歧处理规则预先写明，不在事后临时决定；
- 意图基准的确认由用户本人完成，不由转写员推断。

## 7. 评测指标与报告要求

遵循可行性指南第 8 章。首版必须产出：

1. 独立听者转写的中文 CER（分母口径明确写清）；
2. 关键内容错误率：否定、数字、专名、剂量等逐类统计；
3. 逐说话人与逐严重度分层结果，不只报均值；
4. 与原始语音的配对对照结果；
5. 用户主观可懂度评分与使用意愿；
6. 失败案例清单（含内容改错与退化用户）。

**禁止**：用正常说话人 CER 推断本人群效果；只报合并均值；用训练所用的同一 ASR 作唯一裁判。

## 8. 隐私与数据生命周期

- 原始音频、转写文本、health 相关字段、voice profile 四类分开管理；
- 默认本地优先，训练与上传需独立授权；
- 明确每类数据的保留期限与到期删除方式；
- 导出、删除、撤回均需可验证（能证明已删除，而非仅隐藏入口）；
- 对外发布任何音频、文本或案例片段前，需另行授权并做去标识化处理。

## 9. 当前阻塞项

本协议在下列条件满足前不得启动实际采集：

1. 未成年人参与规则与监护人同意流程未确定（本协议当前只覆盖成年人）；
2. 医疗机构/合作方的伦理审查要求未知；
3. 跨机构数据共享与委托处理协议未签署；
4. 数据存储位置与跨境情况未评估；
5. 报酬与撤回后的补偿规则未确定。

## 10. 最小可行起步（待上列阻塞项解决后执行）

首轮只做 **2 名 L2 说话人 × 3 个会话**，内容为朗读 + 自发表达各 5 条，
用于验证协议本身是否可执行、意图基准能否可靠确认、元数据是否齐全。
本轮不用于任何模型效果结论。
