# VoiceClear P0 执行清单（数据优先路径）



> 目标：拿到**第一批可用数据**，并让通用 ASR 在目标人群上产出可信基线。

> 前置：[数据采集协议](target-cohort-data-collection-protocol.md)、[数据集 Schema](dataset-schema.md)



## 0. 核心判断



A 路径的瓶颈不是代码，是**人**。当前所有技术阻塞项都可以靠「拿到真实数据」解开：



- 端侧模型接哪个 → 需要目标人群数据才能判断；

- 严重度分层怎么做 → 需要专业顾问；

- 置信度阈值定多少 → 需要真实识别结果分布；

- 可懂度提升多少 → 需要基线与盲测。



**因此本清单把「可并行、互不依赖」的事项排开，把「需要外部人员」的事项明确标出等待条件。**

## 2. 关键路径



```

B1 决策合规主体

  └─> B4 伦理审查（周期不可控，通常数周到数月）

  │     └─> B2 招募用户 + B3 专业顾问

  │           └─> 按协议采集 2 名 L2 说话人 × 3 会话

  │                 └─> A5 入库 + A1 校验

  │                       └─> B5 跑 ASR 基线 → 决定端侧模型选型

  │                             └─> P2 质量基线结论



A1/A2/A3/A4/A5 ── 可并行，不依赖伦理审查

C1/C2 ── 需要设备，可并行

```



**B4（伦理审查）是关键路径上最不可控的一环。**

A 组已有工程实现，但“有代码”不等于“可开始真实采集”。伦理审查之外，仍须用真实 App 产出完成
多轮采集、旋转/进程恢复、撤回、重复导出、入库和评测的端到端验收；验收通过前不得采集正式研究数据。



## 3. 立即可执行的第一批采集（P0 最小可行）



按协议第 10 节，首轮只做：



- **2 名 L2 说话人 × 3 个会话**；

- 每会话：朗读 5 条 + 自发表达 5 条；

- 预计音频量：约 0.5–1 小时（便于 1 人 1 天完成转写）；

- **本轮不产出任何模型效果结论**，只验证协议可执行性。



### 首轮要回答的 5 个问题



1. 意图基准（用户确认「我本来想说什么」）是否真的可靠、负担可接受？

2. 元数据能否当场完整记录，还是需要事后补录？

3. 20 分钟采集上限是否合适？疲劳曲线如何？

4. 用户对「文本确认」这一步的接受度如何？

5. 采集 App 的引导流程是否让用户清楚每一步在做什么？



**这 5 个问题答不上来，后面所有模型工作都建立在流沙上。**



## 4. 风险与预案



| 风险 | 预案 |

|---|---|

| 伦理审查周期过长 | A 组工程工作先行；首轮小样本先做协议验证 |

| 招募不到目标用户 | 先用同事与亲友做**流程演练**（非正式数据），确保协议可执行 |

| 用户疲劳导致数据质量下降 | 严格 20 分钟上限 + 疲劳自评；宁可少采 |

| 意图基准确认负担过大 | 若负担过重，改为「二选一候选确认」而非自由文本 |

| 严重度判定无法由顾问支持 | 首批只做 L2，并在报告中明确标注分层缺失 |
